# Tahoe Theme Project

Переносимый проект темы в стиле macOS Tahoe (26) для KDE Neon/Plasma, на базе
темы **MacTahoe** от vinceliuice — прямого преемника используемой ранее темы
WhiteSur (см. соседний проект `../MacOS/`).

Цель: собрать исходники, установить их на систему единым способом и вести
такую же документацию для переноса/восстановления, как в `../MacOS/`.

## Статус

Тема установлена и применена на живой системе 2026-07-28. Активны
Look-and-Feel `MacTahoe-Light`, Kvantum `MacTahoe`, иконки и курсоры MacTahoe,
GTK-тема MacTahoe-Light и SDDM MacTahoe-Light. Подробное состояние и результаты
проверок находятся в `notes/CURRENT_STATE.md`.

## Быстрый старт

1. Открыть `AI_HANDOFF.md` для контекста.
2. Проверить содержимое `source/` — три независимых репозитория со своими
   `install.sh` и опциями (цвет, акцент, blur и т.д.).
3. Установить на систему:

```bash
cd /home/ediskrad/Documents/Theme/Tahoe
./install.sh
```

`install.sh` — обёртка, которая последовательно вызывает `install.sh` каждого
из трёх исходников с параметрами по умолчанию (light+dark, стандартный акцент,
обычные кнопки управления окном). Внутри исходников доступны собственные флаги
для тонкой настройки — смотреть `docs/COMPONENT_MAP.md`.

## Структура

- `source/` — исходники трёх репозиториев MacTahoe (KDE, GTK, иконки+курсоры),
  склонированы без `.git`, хэши коммитов — `notes/SOURCE_REVISIONS.md`.
- `installed/` — описание и манифест реально установленных компонентов после
  применения темы.
- `docs/` — карта компонентов и процесс изменений.
- `tools/` — вспомогательные скрипты проверки состояния.
- `notes/` — ревизии исходников и текущие отличия от апстрима.
- `backups/` — резервные копии перед точечными правками.

## Главный принцип

Пока `installed/` пуст, единственный источник истины — `source/`. После
первой установки на систему нужно снять снимок реально применённых файлов в
`installed/` (по аналогии с `../MacOS/`), чтобы проект можно было перенести на
другую машину без повторной сборки/настройки.

Источник исходников — `source/`, а фактическое активное состояние системы
зафиксировано в `notes/CURRENT_STATE.md` и `installed/README.md`. Полная копия
пользовательских и системных каталогов в репозиторий не помещается: вместо неё
хранятся пути, идентификаторы, команды применения и результаты проверок.

Внешние GitHub-ссылки, кроме апстрима vinceliuice (источник темы) и репозитория
проекта, не добавлять.
